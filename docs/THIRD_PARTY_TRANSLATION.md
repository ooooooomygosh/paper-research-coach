# Optional whole-paper translation

The optional worker loads **BabelDOC 0.6.4** from its own Python environment. It is not included in the base installation. Upstream: https://github.com/funstory-ai/BabelDOC/tree/v0.6.4. The project's MIT license does not relicense BabelDOC or its fonts and other dependencies. Process separation is a reliability boundary, not a claim of exemption from upstream license obligations. Anyone redistributing or providing modified translation software must consider the applicable upstream terms, including source availability.

The entire internal adapter lives in `babeldoc_worker.py`: translator placeholder protocol, pre-translation paragraph capture, post-typesetting glyph capture, and extraction of the two Form XObject transforms used for side-by-side pages. We use upstream's CPU layout path to avoid lengthy CoreML compilation on some Macs, limit layout inference to two CPU threads and disable idle spinning. The native PDF/font pipeline runs on the isolated process's main thread. The synchronous translation API returns completion directly; we supply a progress monitor because the asynchronous iterator in this installed 0.6.4 build did not finish reliably after writing the PDFs.

Before any version upgrade, change the version guard and dependency pin together, then verify the hook signatures, placeholder protocol, output filenames, paragraph identifiers, typeset text, Form matrices, cancellation and the real PDF fixtures in TESTING.md. Unverified versions are rejected. An optional environment failure leaves the reader, coach, notes and existing translations usable.

Only the selected source paper's content is sent to the configured Codex translation model. Translation and alignment use separate tool-free ephemeral native threads and a separate app-server process; they never append to the paper's coaching thread. No API key is read or provisioned by this integration. BabelDOC may download layout, font, CMap and tokenizer resources from upstream on first use and caches them locally.

The adapter's JSON-lines protocol uses request identifiers and an independent reply reader so upstream translation threads can receive out-of-order results safely. Codex requests use independent ephemeral threads on each paper's app-server connection. The host enforces a shared request limit across translation and alignment and a separate limit on concurrent paper workers. Defaults are two papers and four requests; local layout remains limited to two CPU threads per worker. PDFs are exposed after typesetting while atomic alignment checkpoints continue in the background. Restarted jobs with valid saved PDFs skip the BabelDOC stage.
