# 体验与教学闭环审视

审视基线：`e8cc4199e406d739dd9552380295c11dc2782b12`（2.0.0rc4）；本次交付为 2.0.0rc5。本报告区分源码中可确认的问题、这次实现的改动、需要实机/真人验证的假设。它不是学习收益实验，也不是 Zotero/iPad 全兼容认证。

## 产品目标与已有基础

产品应帮助读者形成并修正可检验的研究判断，而不是增加 AI 摘要产量。最短闭环是：一个阅读目标→一句暂定贡献→自己的解释/预测→真实证据→修正→对下一项研究行动的影响。控制台负责证据、原话、位置和恢复，Skill 负责何时讲解、追问和停止。

已有八步主线、原话与 AI 评论分离、笔记授权、事务幂等、版本锚点、插话返回点、Zotero 冲突处理、文件目录同步、提取练习和真人试读协议。这些应复用，不再包装成待新增功能。尤其不能声称项目此前没有主动阅读或没有同步冲突保护。

## 本次修复与实现

| 可确认的断点 | 后果 | 改动与检查 |

| `/8` 计数没有展开依据 | 核查覆盖易被理解成掌握程度 | 显示“已核查”，展开每步依据并回到对应页；明确不等于独立掌握 |

| 安装产物缺少源码包 | 难以对照所安装的 UI、Skill 与源测试 | 按已有 pyproject allowlist 发布 sdist；不含私有状态或依赖缓存 |

图片仍是整页而非裁切；界面已明确告知。只读 Zotero 批注仅定位，不因这个功能获得写权限。读取后的思考不会因已渲染高亮自动变成“已讨论”。代码修复不扩大 Zotero 授权范围或改变同步删除策略；合并与本机升级按本次用户授权执行。

## Skill 的改进重点

**抓关键贡献，但不编发现史。** 把“非显然观察是否成立”“机制是否解释”“公平预算下是否有收益”分开。让学生尝试去掉架构名字后重述可检验主张。最近前作没有访问时留下比较缺口，不先假定作者或学生一定创新。

**主动，不等于每轮考试。** 一条提示、完整示范、检验判断都是合法学习动作；缺前置知识就讲清楚。点击帮助模式只表示本轮偏好，不更新能力等级。工作台提供独立授权的实际表现记录入口：逐字引用本轮回答，关联实际读取页、帮助程度、判断标准与反馈。最近表现可指导下一轮帮助量；没有将单次表现升级成跨论文能力认证。

**八步是完成标准，不是强制成本。** skim 阶段筛掉不相关论文是成功的决策；保持暂停和停止理由，不填满未处理步骤。只有完整核查时才说完成。关闭答案后的回忆与跨例迁移，与看着答案复述分别记录。

**输出为听众服务。** 汇报覆盖研究关联、背景、系统/问题图、关键机制、证据/结论、收获与下一步；方法部分不是 AI 推导笔记的堆叠。先排练一个关键因果过渡，再选择图。没有核实结果不自动生成漂亮结论。

设计依据与访问范围见 [SOURCES.md](SOURCES.md)。Keshav 的经验支持分层投入与重建论证，不能证明本工具有效。Bastani 等的高中数学实验提示应区分辅助表现与移除 AI 后的学习；不能直接外推博士科研训练，也不能证明本项目任一帮助模式有效。

## 后续优先级：不要一次堆满界面

### P1：先解决跨设备、模型和上下文可靠性

**真实试读验收。** 在 Mac 上完整做一次导入→三轮带读→选择批注→错误理解修正→中断恢复→汇报排练。使用真人问题和自己的已授权材料，不以合成 RPC 代替真实模型。按现有 [HUMAN-TRIAL.md](HUMAN-TRIAL.md) 做无 AI 即时、3–7 天延迟和新论文迁移测验，分维度评分并记录帮助量。满意度、会话长度和8/8只作过程指标。对照可选普通 PDF+笔记、普通聊天和本系统；未做试验前不报告效应大小。

**上下文预算与能力证据。** 本次将默认研究记录限制为 36,000 字符以内，优先当前回答、当前页与待讨论原话；迁移历史另限 22,000 字符。明确标注节选、遗漏数和记录编号，界面可展开本轮发送范围。新增当前论文范围内的笔记分页、原话分段和旧对话回查，数据库及用户原文不被改写。能力反馈另需用户开启、精确引用和实际读取页。下一步应针对不同模型测量真实 token 占用、长期对话延迟和跨论文迁移；字符预算不是每种模型的容量保证。

**真实浏览器与模型矩阵。** 本轮在 Edge 用独立合成 PDF 实际验证正文搜索、阅读位置返回、图表框选、附图对话、学习反馈保存与刷新恢复，并复用 gpt-6.1-sol 完成两轮真实回复。这不代表 Safari 的 PDF 选择、iPad Apple Pencil 手写或触控区选已被验证。后续应把浏览器链路纳入持续回归，再做 Safari/iPad 人工验收。多页/旋转/CropBox/扫描 PDF、网络中断、拒绝模型发送、睡眠恢复是必要场景；本次适宽和 pointercancel 不应被称为完成平板适配。

### P1：Zotero 与文件的产品边界

**多 PDF 必须明确主附件。** 当前自动采用第一个 PDF（见 `zotero.py`），而预印本、出版版、补充材料不是同一份坐标空间。下一步给附件选择器，显示文件名、页数、来源指纹和当前笔记影响，确认后重新绑定；禁止仅凭 DOI 或标题合并锚点。

**同步状态对读者可解释。** 保留现有实例ID、基线版本和冲突机制；在相关笔记显示“只在本机/待写回/已同步/冲突/外部只读”，能跳到冲突处理，不在每次发送前弹窗。一次删除应显示对象和影响范围；重试不能新建重复条目。Zotero 10 本地版本不能与云端版本比较，授权本身不限定集合，应用级范围保护必须保持。

**Mac 与 iPad 的分工。** 当前本机服务绑定回环地址，并不是 iPad 可直接连接的同步服务。优先让 Zotero 管理书目/PDF及已有原生批注，让 PRC 管理研究判断和带读状态。要跨设备使用 PRC，需另做鉴权、传输安全、冲突语义和离线队列设计；不要以开放 localhost 或共享含凭证启动链接来实现。Apple Pencil 书写不是已有框选功能。

**不要混淆三种存储。** SQLite 是运行时权威状态，Markdown 是可携带输出/显式同步视图，Zotero 是有版本的协作方。文件删除/移动/同名应保留历史和来源指纹。下一步优先把导出清单与恢复演练做清楚，再做多库图谱。备份必须明确是否含 PDF、私有笔记和授权信息；钥匙/登录片段永不进入导出。

### P2：阅读效率，而不是第二个文献管理器

本次补上 PDF 目录、可停止的本机正文搜索和前后阅读位置，换版时清空旧搜索和跳转历史，扫描页明确说明搜索限制。选区附近的“提问/新笔记”工具、可调分栏宽度仍需验证是否减少一次真实证据定位的步骤。文献图谱应只展示有出处的关系，先支持少数论文同字段比较，再考虑自动全库图。书籍章节/博客可作为外部证据，但需要 URL/版本/访问范围与引用位置，不能无痕写成论文事实。

跨学科、语言切换、无障碍和一键安装的优化放在上述闭环稳定后逐项验收。不能为了“全能阅读器”在当前页同时展开论文列表、知识图谱、任务面板、笔记树、终端和聊天。

## 验证与边界

新增测试覆盖旧文字请求的选区归一化与原幂等指纹、容量节选与不改原文、跨论文回查拒绝、独立学习授权、回答逐字验证、实际页与帮助限制；并保留请求级帮助枚举、逐轮生效、原话不变、老请求幂等、跨页附图拒绝；组件覆盖默认/显式意图、IME、异步发送期间的新选区、来源重绑确认、已存批注过滤/定位、适宽与键盘范围。合成论文不代表真实研究结果。

测试命令：`PYTHONPATH=src pytest -q`；`npm --prefix frontend test`；`npm --prefix frontend run build`；`python scripts/validate_skill.py`。CI 使用仓库已有 Python 3.10/3.12 与 Node 24 矩阵。最终执行结果写在 PR，而不是预先在此声称通过。新增 `evals/scenarios.json` 场景只是待运行行为用例，不等于 `evals/results.json` 已包含新的模型评估。

## rc5 交付重点与仍需补足的闭环

| 角度 | 已落地 | 下一项具体缺口与验收方向 |
|---|---|---|
| 带读与思考 | 最近前作、观察、机制、同预算收益分开核查；本轮帮助选择；按真实回答记录局部表现 | 让学习者在另一篇论文独立解释并设计检验，检查帮助是否真正减少；不以会话长度代替能力 |
| 对话与记忆 | 一轮一个动作；原话与 AI 评论分开；重启恢复；36,000 字符研究上下文及 22,000 字符迁移历史；按需回查 | 用数百条笔记和长对话测延迟、实际 token 与漏取率；为用户的跨论文研究目标提供有出处的长期记忆 |
| 证据定位 | 页/版本绑定、旧消息归一化、持续批注、目录、搜索、返回位置 | 搜索命中词高亮、可调分栏、目录异常/超长书籍性能；触控和旋转/CropBox 实机验证 |
| 思考批注 | 浏览选区不自动改已有原话出处；重绑明确；保存与讨论状态分开 | 笔记级展示本机、待同步、同步完成、冲突状态；用实际远端版本证明状态 |
| Zotero | 实例与集合范围、原生批注、未知创建结果防重复、版本与冲突保护 | 显式主 PDF 附件选择，区分预印本/出版版/补充材料，换绑前展示笔记影响；更多特殊批注往返 |
| 文件与恢复 | 原 PDF 只读；按内容识别；追加 Markdown 修订；源码、wheel、Skill ZIP | 产品内一键备份与恢复清单，包含哪些 PDF、笔记、对话；在独立目录演练恢复并核对记录与来源 |
| 网络与书籍 | Skill 区分 PAPER/EXTERNAL/INFERENCE；来源账本记录访问范围 | 控制台尚无通用网页/书籍证据导入与最近前作全文回查；应保存 URL、版本、访问日期、具体章节/段落与关联论断 |
| 研究启发 | 朴素强基线、替代解释、可证伪最小检验和停止条件；有证据的文献关系 | 先做少数论文同字段对比与研究演化链，形成一个可检验问题，再决定是否需要全库知识图谱 |
| 学习效果 | 有实际回答、帮助量与可回看反馈；保留真人试读协议 | 无 AI 即时、延迟及新论文迁移测试；使用独立评分，观察判断准确性和自主性 |
| 部署 | 发布版本来自安装包；服务版本一致；启动日志不输出访问凭证 | 真实 Safari、iPad、Windows 与 Claude/Pi 分别验收；跨设备 PRC 仍需独立鉴权、传输与离线冲突设计 |

阅读方法的依据应服务于这些动作：[Keshav](https://web.stanford.edu/class/ee384m/Handouts/HowtoReadPaper.pdf) 支持分层投入和决定是否继续；[认知学徒制](https://www.aft.org/ae/winter1991/collins_brown_holum) 支持示范、辅导和逐步撤去帮助；[QALMRI 原始章节](https://attentionandlearninglab.com/papers/2017_BrosowskyParshina.pdf) 支持把问题、替代解释、检验逻辑和推论接起来。它们提供设计依据，本项目的学习收益仍需真人试验。
