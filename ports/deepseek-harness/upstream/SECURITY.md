# Security and private data

The workbench is a local, single-user application—not a remotely hosted multi-user service. Do not expose its port or Zotero’s port to the network.

Read [data storage, credentials, model access and backup boundaries](docs/SECURITY.md) before sharing diagnostics. Never attach a database, session-token, private launch URL, model credentials, private paper or an unapproved conversation to an issue.

For a suspected vulnerability, use GitHub’s **Report a vulnerability** option when available. If private reporting is not enabled, open a minimal issue requesting a private reporting route without exploit details or sensitive data. No dedicated security email address or response-time guarantee is claimed.

Include the affected commit or package version, a synthetic reproduction and the expected access boundary. Do not test against another person’s library or external service without authorization.
