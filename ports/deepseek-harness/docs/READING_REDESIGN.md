# 阅读界面与交互式讲解改版

Paper Research Coach 1.2.0 的 DeepSeek Harness 适配源码。目标是让读者先看材料、做一个判断，再按需打开工具。名称、账户通道、已有论文、学习记录和八步阅读状态沿用原实现。

## 阅读依据与取舍

[南京大学-机器学习《如何读论文？》](https://dy8q0bnq8y.feishu.cn/wiki/Ow8fw2HtEiixDgkWlkbckdvHnef)提出宏观概览、锁定问题、已有工作、方法、实验、追踪线索和读后思考七个环节，并强调批判与创造性思考。本项目的 [METHOD.md](https://github.com/ooooooomygosh/paper-research-coach/blob/main/docs/METHOD.md)强调目的与深度、暂定贡献句、看证据前预测、简单基线与替代解释、每轮一个认知动作、保存读者原话，以及回忆和可证伪的下一步。

二者综合为随时可导出的阅读提示，不再新增一套必须依次完成的进度系统：

| 阅读环节 | 在既有八步中的位置 | 本轮要形成的判断 |
|---|---|---|
| 宏观概览 | 阅读目标、独特贡献 | 是否值得继续；作者主张改变了什么 |
| 锁定问题 | 问题设定 | 输入、输出、信息、假设、代价是什么 |
| 已有工作 | 独特贡献、问题设定 | 最接近的路线和简单基线是什么 |
| 方法机制 | 方法机制 | 设计怎样解决困难；何时成立 |
| 实验与推理 | 证据核查、边界与判断 | 比较是否公平；能否排除替代解释 |
| 追踪线索 | 按需支线、研究启发 | 还缺哪条直接相关的依据；何时停止 |
| 读后思考 | 研究启发、回忆与复习 | 能独立复述什么；下一步怎样检验 |

“标准阅读”导出 UTF-8 TXT，附当前文献标题、来源版本和物理 PDF 页码。提示是注明来源的综合改写；按钮本身不调用账户、不自动修改阅读进度，也不强制复现每篇论文或采用固定时间比例。需要时可将导出的提示用于自己的阅读对话。

## 已实现的界面

- 顶部保留阅读、知识库学习、交互式讲解三种工作区，旁边放置翻译和显示原文。翻译点击展开，包含当前论文与批量后台翻译两个范围。
- 原文在讲解和知识库旁独立显示；阅读视图中的按钮返回原始 PDF。没有当前 PDF 时原文入口不可用。
- 移除工作区重复的宣传标题与常驻列表，使用紧凑标题和选择器。已生成讲解收起修改表单，先展示内容；页内继续提问会展开输入区，用户核对后发送。
- 控件图标保留 Lucide 形状与原始 ISC 许可说明（包含 Feather 部分的 MIT 署名），以独立 SVG 源文件随包提供。正文流程图与数据曲线仍按内容绘制。
- 按钮与边框采用纯色和细线，不使用高光、渐变或发光阴影；键盘焦点使用清晰的实线轮廓。知识库嵌入页也覆盖原模板的玻璃与阴影效果。
- 保留研究、记录、同步和设置，通过按需入口打开；已有 PDF 高亮按行合并与去重的修复继续保留。

翻译复用既有任务队列、缓存、重试和并发设置。关闭面板、切换论文或工作区不会取消已提交任务。完全退出 Harness 会停止计算，持久化进度可在下次启动后恢复；没有额外的系统常驻服务。

## 可操作讲解

在“讲解形式”中可选原有的“图文文档”或新增的“可操作组件”。旧记录保持文档模式，仍可编辑 Markdown、修订和导出。组件模式由 Harness 登录账户生成结构化数据，经校验后交给内置渲染器，不执行模型生成的脚本。

| 组件 | 适用内容 | 实际可操作行为 |
|---|---|---|
| 概念 | 术语、概念区别 | 点选节点，展开解释，保存当前节点 |
| 步骤 | 方法或推理机制 | 切换步骤，展开当前机制，保存阅读位置 |
| 比较 | 方法差异和比较条件 | 过滤相同项，选择一行查看解释 |
| 参数 | 函数关系的教学探索 | 滑动参数，本地更新曲线，保留初始参考线 |
| 证据 | 关键判断与备选解释 | 先选择，再看参考解释；也可直接求助 |

参数探索当前仅支持线性、幂函数和指数函数，校验定义域、有限数值、默认值、单位与参数范围。坐标轴覆盖所设参数空间并保持固定，虚线表示初始参数。页面始终注明“教学示意”，不能将示意曲线当作原论文实验。其他关系继续使用图文文档、表格或步骤说明。

组件页可将当前参数、选择或步骤带回可编辑提问区；该动作不自动发送。页内状态通过已有隔离页面通道保存，以发布版本区分。HTML、Markdown 和组件 JSON 可导出；每次生成创建新发布版本，历史页面只读并保留状态。

## 来源与失败处理

论文组件的证据来自实际 PDF 文字，用户选区文字与标题元数据不充当证据。知识库组件使用选定发布版本中的检索片段。引用必须逐字匹配指定来源；匹配后保存物理页、来源版本和原文，引文校验失败允许一次修订，仍失败则保留上次成功的页面。

异步生成发布前再次检查绑定来源，论文换版或知识库发布版本不可用时拒绝更新。定位请求使用所选发布版本保存的锚点，不采信嵌入页自行提交的锚点。当前主界面没有选中对应论文，或版本不符时，会提示先选择对应来源。

逐字匹配只证明引文出现在本次提供的片段中，不证明解释由引文推出，也不证明整篇论文或知识库都已覆盖。独立问题标为未绑定原文。参考答案不作为掌握度评分。

## 与近期交互式界面的关系及开发方案

OpenAI 在 [2026 年 10 月 7 日的产品介绍](https://openai.com/index/gpt-6-for-everyone/)中描述了按问题选择文字、视觉和控件，并逐步呈现界面的 Intelligent UI。这里借鉴的是按问题选择表达方式、直接操作和渐进展开的交互原则；本插件使用自己的有限组件契约，没有接入该产品的内部组件系统或编译器。

| 阶段 | 内容 | 验收方式 |
|---|---|---|
| 本次交付 | 紧凑布局、全局翻译/原文入口、标准阅读、五类组件、来源与版本、导出 | 本地回归、真实渲染器交互与合成页面观察 |
| 下一阶段 | 简单问答先给短文字；复杂问题再建议生成组件；显式显示“原文事实／解释／假设” | 同一问题比较简短回答和组件，核对标签与来源 |
| 后续 | 分模块生成与渐进显示；每块校验后出现，失败保留已完成部分 | 中断、重试、跨块来源与历史回归 |
| 后续 | 面向具体学科的公式与真实表格数据绑定，以及较长材料的多模块组合 | 由人工核对公式/单位与原文数据，添加对应端到端用例 |

本次页面在全部校验通过后完整发布，不声称已实现流式组件。扩展公式时先添加明确的计算规则及测试，不引入任意脚本执行。学习效果需要另行评估，不能从点击数或测试通过数推断。

## 验证与发布范围

本地 Windows 源码验证：233 项 Python 测试通过、3 项跳过；120 项前端测试、20 项 Node 测试通过，TypeScript 与生产构建通过。Windows 使用既有验证脚本的 POSIX 安装测试排除规则。真实页面 DOM 检查覆盖参数更新、初始参考、概念/步骤、比较筛选、先答后揭示及状态带回；API 检查覆盖生成、有限修订、来源换版、失败保留、历史与导出。

浏览器检查使用隔离的合成 PDF 和合成账户响应，观察原文切换、讲解、翻译入口与页面排版；不连接真实账户，不改写已安装 Harness，不验证原生账户鉴权。本次提供源码和 PR，版本元数据为 1.2.0，未发布新的二进制安装 ZIP。Windows ZIP 安装器与主线新合入的 [macOS 源码安装](https://github.com/ooooooomygosh/paper-research-coach/blob/main/ports/deepseek-harness/macos/README.md)均保留，宿主基线为 Harness 0.2.1-rc.5；本次未在本机执行 macOS 原生宿主验收，两个平台的 CI 均纳入新增检查。用户另行要求在 PR 之后进行本机安装与调试（R017），该后续验收不将个人账户数据或论文提交到仓库。

### 影响内容含义的实现选择

以下默认选择均由本次实现者作出（`ask: never`），可从源码调整：

- **R003**：七环节提示与现有八步结合，不新增强制进度；不强制时间比例或每篇复现；导出是本地操作。
- **R004**：后台指 Harness 运行时的持久任务队列；全应用退出后停止计算，进度可恢复，不创建系统服务。
- **R006**：参数结果是教学示意；参考解释由模型生成，均不作为实验结果或学习掌握度。
- **R008**：引用只做所提供片段的逐字匹配，并绑定版本/页码；不保证语义蕴含或全文覆盖。独立问题没有已核对来源。
- **R009**：每次发布保留独立的页面、数据与版本；阅读状态按发布版本保存，历史仅查看/导出，新生成使用当前草稿和选定来源。
- **R012**：曲线纵轴固定为所设参数空间的范围，虚线为初始参数，便于观察变化；该可视化不增加实验依据。
- **R016（复核发现）**：Markdown 导出保留比较解释、参考选项、参数公式/定义域/坐标/范围/单位与来源版本，表示发布时的静态内容；不将读者当前操作写回旧发布内容。

界面选择为：保留旧功能按需展开（R002），文档与五类组件可选（R005），只支持三个明确函数族（R007），原文独立开关（R010），源码 PR 与版本升级不等于二进制发布（R011），成品优先展示与提问展开（R013），独立 SVG 控件资源（R014）。本次工作在已合并 PR #17 基础上另开 PR（R001），提交前同步主线的 macOS 安装与账户修复（R015）。

### 复核记录

共执行两轮假设复核：首轮发现 1 项未声明的语义选择和 3 条与代码不符的记录，涉及静态导出完整性、当前草稿、来源版本与许可措辞，均已修复并增加检查。第二轮检查返回 0 项新发现、0 条不符记录；复核者另运行了 20 项组件测试并通过。

复核为 GPT 同系列的暂定检查，调用仅提供了所请求模型的身份，没有回传可独立核实的精确模型版本；不作为独立正确性或教学效果结论。模式为 `ask: never`：17 项选择中 15 项为实现默认、1 项来自复核、1 项来自用户后续安装要求。没有遗留生产占位实现。任意公式、视频、远程分享、自定义主题目录、系统后台服务与独立教学效果评估暂未实现；后续按上面的开发阶段推进。
